# 原型模式（Prototype）

## 一、意图

用原型实例指定创建对象的种类，并通过拷贝这些原型来创建新对象。原型模式将"克隆已有对象"作为创建新实例的方式，避免重复执行昂贵或复杂的初始化过程，同时也允许在运行时动态新增/替换产品类型——只要新增一个原型并注册即可。

## 二、使用场景

- 创建新对象成本较大（如涉及数据库查询、网络请求、复杂计算），而已有实例可作为模板时。
- 系统中存在大量相似对象，只有少数字段不同，复制原型后微调更高效。
- 需要保存对象某一时刻的快照（如撤销/恢复、草稿复制）。
- 类的初始化需要动态参数，希望避免与具体类耦合，运行时通过克隆原型生成。

## 三、结构

```
        ┌────────────────────────┐
        │   Prototype (abstract) │  implements Cloneable
        ├────────────────────────┤
        │ - name: String         │
        ├────────────────────────┤
        │ + clone(): Prototype   │ ← 浅拷贝默认实现
        │ + describe(): String   │
        └────────────────────────┘
                    △ △
        ┌───────────┘ └────────────┐
        │                          │
┌────────────────┐         ┌────────────────┐
│ConcretePrototypeA│       │ConcretePrototypeB│
├────────────────┤         ├────────────────┤
│ - tags: List    │         │ - tags: List    │
├────────────────┤         ├────────────────┤
│ (继承浅拷贝)    │         │ + clone(): 深拷贝│
└────────────────┘         └────────────────┘
```

## 四、角色说明

- **Prototype（抽象原型）**：实现 `Cloneable`，声明（或提供默认）`clone()` 方法，作为所有具体原型的基类。
- **ConcretePrototype（具体原型）**：继承抽象原型，可重写 `clone()` 实现深拷贝。
- **Client（客户端）**：通过调用原型的 `clone()` 获得新对象，无需关心具体子类与构造细节。

## 五、代码示例

本仓库在 `src/main/java/com/example/creational/prototype/` 下实现：

- `Prototype.java`：抽象原型，实现 `Cloneable`，提供默认浅拷贝 `clone()`。
- `ConcretePrototypeA.java`：使用继承的浅拷贝，演示引用字段共享行为。
- `ConcretePrototypeB.java`：重写 `clone()` 实现深拷贝，演示引用字段独立复制。
- `PrototypeDemo.java`：演示入口，对比浅拷贝与深拷贝的差异。

## 六、优缺点

**优点：**

- 通过克隆快速生成对象，避免重复的昂贵初始化。
- 运行时可动态新增原型类型（只需注册新原型并克隆），符合开闭原则。
- 可保存对象某一时刻的内部状态，便于撤销/快照功能。

**缺点：**

- 每个类都需要正确实现 `clone()`，引用字段需手动深拷贝，易出错。
- `Cloneable` 是标记接口无强制约束，深浅拷贝行为依赖开发者自觉。
- 复杂对象图中若存在循环引用，深拷贝实现难度较大。

## 七、应用实例

- **JDK**：`Object#clone()` 是原型模式的基础；`java.util.ArrayList`、`HashMap` 均实现了 `Cloneable` 并提供 `clone()` 方法。
- **JDK**：`java.util.Calendar#clone()`、`java.util.GregorianCalendar#clone()` 典型原型。
- **Spring**：`@Scope("prototype")` 让每次获取都产生新实例（语义层面借用原型概念）。
- **原型注册表**：许多框架维护 `Map<String, Prototype>`，按 key 克隆对象，如配置化报表/模板复制。

## 八、与相关模式对比

| 模式 | 关键差异 |
|------|----------|
| 原型 | 通过克隆已有对象生成新实例，关注"复制"。 |
| 工厂方法 | 通过 new + 构造方法生成新实例，关注"封装创建"。 |
| 抽象工厂 | 一次性返回一族产品；原型可与之结合，让工厂内部用克隆生成产品。 |
| 建造者 | 关注分步构建复杂对象；原型关注"以现有对象为模板快速复制"。 |
